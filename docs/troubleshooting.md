# 配置与故障排查

## 配置和数据

默认目录为 Windows 的 `%LOCALAPPDATA%\Tramoing\` 和 macOS 的 `~/Library/Application Support/Tramoing/`。开发环境可以用 `TM_DATA_DIR` 覆盖；`TM_DB_PATH` 可单独覆盖数据库位置。

首次启动会从改名前的旧目录导入数据库、设置、网络限制展示缓存、待写入历史及导出文件，使用 SQLite 快照保留 WAL 中的数据；旧目录保留为备份，新目录已有文件优先。迁移完成后不会重复导入。旧程序仍在运行或旧数据库损坏时会停止启动并在新目录的 `ui.log` 记录原因，避免产生两套相互分叉的历史；先退出旧程序或修复旧库后再启动。`TM_DATA_DIR` / `TM_DB_PATH` 指定的隔离实例不执行自动迁移。

| 文件 | 内容 |
| --- | --- |
| `settings.conf` | 界面和采样设置，`key=value` 纯文本 |
| `history.db` | SQLite 流量历史 |
| `ui.log` / `ui.log.1`–`.3` | 主程序启动、采样、设置、导出、更新、窗口框架警告及 Rust panic 堆栈 |
| `helper.log` / `helper.log.1`–`.3` | Windows 采集助手启动、ETW、管道和网络控制日志 |
| `etw-dump.log` | Windows `--dump-events` 事件诊断日志 |
| `network-rules-cache.json` | Windows 断网规则的展示缓存，实际规则保存在系统 WFP 中 |
| `update/<version>/` | 校验通过的更新安装包 |

设置页签依次为：任务栏或菜单栏（网速、性能与配色）、统计（列表数量、历史、流量提醒）、通用（主题、语言、自启、更新）。首次进入默认显示任务栏或菜单栏设置，之后保留本次运行中选择的页签。开启对应显示功能后才展开其配色和刷新选项。界面修改设置后立即保存。手动编辑时先退出程序，避免运行中的设置覆盖文件；未知键和无效值会被忽略。常用配置：

| 键 | 取值 | 默认 |
| --- | --- | --- |
| `theme` | `system` / `light` / `dark` | `system` |
| `lang` | `auto` / `zh` / `en` | `auto` |
| `tray_mode` | `both` / `speed` / `icon`，macOS | `both` |
| `tray_badge` | `on` / `off`，Windows 任务栏网速 | `on` |
| `tray_color` | `on` / `off` | `on` |
| `performance_enabled` | `on` / `off` | `off` |
| `performance_interval` | 1 / 2 / 5 秒 | 2 |
| `performance_color` | `on` / `off` | `on` |
| `taskbar_order` | Windows 统计项顺序，任务栏拖拽后自动保存 | `speed,performance` |
| `cpu_color` / `gpu_color` / `download_color` / `upload_color` | `auto` / `#RRGGBB` | `auto` |
| `max_apps` | 5 / 10 / 20，优先保留置顶项 | 10 |
| `pinned_apps` | 按置顶顺序排列的完整应用键，JSON 字符串数组 | `[]` |
| `retention_days` | 1–365 天 | 30 |
| `alert_mb` | 近 10 分钟单应用流量阈值，0 关闭 | 0 |
| `update_check` | `on` / `off`，自动检查 GitHub Releases | `on`（保留旧配置中的 `off`） |

CSV 导出优先保存到当前用户的 Downloads，失败时退回数据目录下的 `exports/`。演示模式不产生持久历史；命令行导出读取已有数据库。

应用列表每行末尾的图钉可切换置顶。置顶项按选择顺序固定在前面，所有时间窗口共用这份选择；其他应用继续按流量排序。应用没有流量或已关闭时，置顶行仍保留并显示 0；加载或采集异常时仍显示骨架或错误提示。置顶项占用展示名额，若数量超过 `max_apps`，仍会全部保留，可滚动查看。选择立即保存，更新或重启后继续保留。

Windows 任务栏上的统计项可直接按住拖拽排序，松开后自动保存，重启后保留；设置页不提供排序选项。拖出统计区域后松开会取消换位。暂时关闭某项显示不会清除它的排序位置。旧版 `taskbar_performance_first` 会自动迁移为项目顺序。

## 导出日志并反馈问题

1. 出现错误时，在弹框中选择 **导出日志**。也可点击主面板错误信息下的 **导出诊断**，或打开 **设置 → 通用 → 日志与故障反馈**。重复的同一错误在 5 分钟内不会连续弹框；选择“暂不导出”不会生成报告。
2. 等待导出完成，点击 **打开文件位置**（设置页中为 **显示文件**）。将 `Tramoing-diagnostics-*.txt` 和发生时间、操作步骤、预期结果一起提供给开发者。报告也留有复现说明栏，可补充后发送。
3. 报告默认保存到 Downloads（没有该目录时使用用户目录），写入失败会尝试数据目录的 `diagnostics/`，再尝试系统临时目录。`TM_DATA_DIR` / `TM_DB_PATH` 隔离实例只写自己的 `diagnostics/`。

主窗口启动失败时会显示原生提示，可直接选择导出；Rust panic 会保存日志并尝试启动独立报告进程，若进程无法启动，下次打开时提示上次崩溃。强制结束进程、断电或部分原生崩溃无法保证弹框。

命令行保留为备用方式：在安装目录运行 `tramoing.exe --export-diagnostics`；macOS 运行 `/Applications/Tramoing.app/Contents/MacOS/tramoing --export-diagnostics`。此命令不打开流量数据库，也不依赖数据迁移成功，因此数据库损坏时仍可收集诊断。Windows 发布版没有控制台，执行后直接到 Downloads 或上述备用目录寻找报告。

报告包含版本、系统和架构、当前采集/存储错误、有限的设置摘要及最近日志。Windows 还会只读检查相邻助手文件、任务的执行路径与最后结果、任务账户是否匹配当前账户、助手进程及其账户、系统服务、命名管道是否存在和最近的任务事件。查询不可用、无权限或超时会写入报告，不能据此认定该项正常。不会修改计划任务、防火墙或进程。

日志默认启用；每个日志文件最多约 1 MiB，保留三份旧文件。每条日志包含 UTC 时间、级别、模块、进程和线程；Rust panic 会记录位置和可获得的堆栈。系统强制终止、断电及部分原生崩溃可能没有最后一条记录。数据目录不可写时尝试系统临时目录中的 `Tramoing-diagnostics/`。设置 `TM_LOG=1` 可额外记录依赖库的 INFO 信息并同步输出到终端。

导出每份日志末尾最多 128 KiB，不包含流量数据库、完整设置、置顶应用列表或网络规则缓存；会替换当前用户主目录并去除识别到的 HTTP URL 中的凭据、查询参数和片段。错误上下文仍可能包含其他路径或程序名，报告可在发送前查看。没有自动上传或自动提交 Issue。

对于尚未安装诊断功能的旧版用户，可先单独发送仓库中的 `scripts/diagnose-windows.ps1`，由用户在 PowerShell 中运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\diagnose-windows.ps1
```

报告写入桌面。这个旧版排查脚本的输出可能包含路径和账户标识，请发送前检查。

## Windows 应用断网

默认不添加任何网络限制。应用行右侧的网络图标可切换联网权限，悬停显示“断网”或“恢复联网”提示：普通地球图标表示允许联网，带斜线表示已断网；转圈表示正在处理，带小圆点表示规则待核验。断网会添加持久 WFP 阻断规则，恢复会移除 Tramoing 为该程序创建的规则。规则覆盖 IPv4 / IPv6 的发起与接收连接，不排除回环，因此普通本机 HTTP/SOCKS 代理连接也在阻断范围内。修改策略后系统会重新授权已有连接；应用已缓存的内容仍可能继续播放，这不代表还在联网。

规则按完整 exe 路径匹配，对所有运行该路径的实例生效，不按临时 PID 或展示名称匹配。不同路径的辅助程序、共享服务、应用更新后的新路径需要分别设置；不保证阻止程序通过其他进程的非网络 IPC 请求代发网络。TUN、第三方网络驱动组合应在对应环境验证。若只看到 `verge-mihomo` 等代理，可点击标题旁的添加应用图标，在面板中粘贴原客户端 exe 完整路径（支持带引号的路径），点击“添加到列表”或按回车添加并置顶；路径有误时会在输入框下提示。对代理本身断网会影响所有依赖它的应用。

只有助手成功写入并核验四条系统规则后才确认已断网。规则不完整、助手离线或请求失败时显示待核验/错误，点击标题旁的添加应用图标，在面板下方“联网控制”区域查看原因或刷新。受限条目即使没有流量、采集异常也仍可见。删除设置文件或展示缓存不会移除系统限制。规则由 Windows 保留，退出 Tramoing、重新启动应用、切换网络或重启电脑后仍存在；正常卸载会先清理本程序创建的规则，清理失败则保留安装文件和恢复入口。

界面和助手须为同一目录下的新版 `tramoing.exe` / `tramoing-helper.exe`，且属于同一账户。出现“未连接到网络控制助手”时应覆盖安装新版，重新编译不会升级正在运行的旧助手。演示模式禁用实际网络控制。若需要在界面不可用时清理全部 Tramoing 断网规则，可在管理员终端运行安装目录中的：

```powershell
.\tramoing-helper.exe --clear-network-blocks
```

恢复联网只移除本程序的限制，不修改其他防火墙软件或管理员设置的规则。

## Windows 无流量

24 小时累计来自历史库，不能证明当前助手正在采集。先查看面板的具体错误：

| 提示 | 检查方法 |
| --- | --- |
| 未连接到采集助手，错误 2 | 确认助手已安装、计划任务正在运行，必要时重新运行安装器 |
| 无法访问采集助手，错误 5 | 确认界面和助手属于同一 Windows 账户；用当前账户重新安装 |
| 采集连接被占用，错误 231 | 检查其他账户或旧版本是否仍连接助手 |
| 暂时中断、正在重新连接 | 查看 `helper.log` 和 `ui.log`；程序会退避重试 |

正常使用建议通过安装器部署。源码开发时，管理员终端运行 `tramoing-helper.exe --install` 会将该可执行文件的当前路径写入 `TramoingHelper` 计划任务；移动或删除它会导致下次启动失败。安装时会停止、删除旧名称的任务并清理旧 ETW 会话。`--uninstall` 取消助手的登录任务，界面程序的 `--autostart` 是另一个独立开关。

```powershell
schtasks /Query /TN TramoingHelper /FO LIST
powershell -ExecutionPolicy Bypass -File scripts\diagnose-windows.ps1
```

诊断脚本兼容 PowerShell 5.1，只读检查系统、安装文件、任务、进程和最近日志，将报告写到桌面，不修改助手或系统任务。报告可能包含本机路径和进程名，提交 Issue 前请检查内容。

当前任务定义允许电池供电并取消默认运行时限。旧安装需要重新注册或覆盖安装，重新编译源码不会自动更新已经注册的系统任务。任务状态 `0x00041301` 表示正在运行。

## 界面和性能显示

- **修改源码后行为未变**：正在运行的程序不会自动加载新二进制。先从界面退出，再启动新构建；第二次启动通常只会唤起原实例。
- **任务栏数字未出现**：确认开启了对应显示选项。Windows 会检查任务栏空间和布局，无法安全挂接时在面板中提示；第三方任务栏工具和 Explorer 重建可能影响显示。
- **macOS 菜单栏不可见**：优先使用打包的 `.app` 验证，检查菜单栏可用空间及当前 Space。单独的面板预览不等同于菜单栏验收。
- **macOS 显示“使用大量能耗”**：在活动监视器中同时检查 Tramoing 和它启动的 `nettop`。旧采集代码将 stdin 接到 `/dev/null`，部分 macOS 版本会在 EOF 上持续唤醒，导致 `nettop` 占用约一个 CPU 核心。修复后保持输入管道打开，仍每秒采样；需要重新构建、安装并退出旧实例后启动新版。系统能耗提示会参考一段时间内的活动，不一定立即消失。
- **温度显示或隐藏**：在“菜单栏 / 任务栏 → 性能监控”开启 CPU/GPU 后，可独立切换“显示温度”。设置立即保存，关闭温度采集不影响使用率。温度列需要额外任务栏空间。
- **温度显示 `--°C`**：表示没有有效读数，不代表 0°C。macOS 使用只读 AppleSMC，当前适配 Intel 及 M1–M5 系列已知传感器；新型号或不可访问的传感器可能暂不支持。Windows GPU 需要支持温度查询的 WDDM 驱动；CPU 没有通用的系统接口，可运行 LibreHardwareMonitor / OpenHardwareMonitor 并启用其 WMI 提供程序。Tramoing 不安装或启动这些监控工具，也不把 ACPI 主板温区当作 CPU 温度。WMI 温度约每 2 秒更新，缺失的提供程序每 60 秒重试；卡住的查询会被终止。温度来源和读取失败状态会记录到本地日志并进入诊断报告。
- **GPU 显示 `--%`**：系统或驱动没有提供可用计数器。它与网络采集助手是否连接无关。
- **空列表或速率为零**：确认存在外网流量，并等待采样建立基线；本机回环访问不计入。置顶应用没有流量时会保留零速率行。
- **没有自动检查更新**：在设置 → 通用 → 启动与更新中开启自动检查，旧配置中的关闭选择会保留。默认启动 10 秒后检查，24 小时内不重复；也可点击“检查更新”立即检查。
- **更新清单尚未发布**：当前 GitHub Release 尚无 `latest.json` 附件，需要维护者通过新版发布流程发布新版本；不是“已是最新版”。
- **未配置更新源**：检查 `TRAMOING_UPDATE_URL` 是否被设置为空值；移除运行时覆盖后恢复构建配置或默认 GitHub 地址，见[开发指南](development.md#更新源)。
- **更新下载失败**：确认可以访问 GitHub Releases 及其附件下载域名。程序会拒绝大小或 SHA-256 不匹配的文件，详细原因保存在数据目录中的 `ui.log`。
- **Windows 更新授权被取消**：程序会继续运行，已校验的安装包保留，点击更新提示可重试。正常升级只需确认系统管理员授权，之后自动覆盖原安装并重启，无需再次选择安装目录和组件。
- **更新提示程序尚未退出**：安装器等待旧程序保存历史并退出，15 秒后仍未结束则停止更新，保留原安装文件；先正常退出 Tramoing，再重新运行已下载的更新包。已有安装会被自动识别并进入升级流程。
- **macOS 安装后找不到窗口**：Tramoing 常驻屏幕顶部菜单栏，不显示 Dock 图标。新版安装完成和首次启动会展开主面板一次；失焦后从菜单栏再次打开。
- **macOS 更新目录无法写入**：已有应用可能由另一个账户安装或目录受管理。自动更新准备阶段会停止并保留正在运行的旧版，请用有权限的账户通过 Finder 替换原应用。普通账户的首次安装可自动使用 `~/Applications`。
- **macOS 更新未完成**：先查看 `ui.log`。下载校验、签名或版本核对、复制失败不会退出原程序；替换或系统打开命令失败时尝试恢复旧版。若无法恢复，提示中的 `.tramoing-install-…/previous.app` 是保留的旧应用，不要删除它。
- **macOS 提示无法验证开发者**：默认构建采用 ad-hoc 签名。要让正式分发获得系统认可，需要发布者使用 Developer ID 签名并完成 Apple 公证；打包脚本支持这两个步骤，不会自动移除隔离属性或关闭 Gatekeeper。

## 统计限制

本工具用于观察应用流量趋势，不应作为计费或精确审计依据。

- **统计口径**：macOS 采用 nettop socket 字节数，Windows 采用 ETW 网络事件；它们与网卡包含协议开销的计数器可能不同。本机回环转发被排除，以减少代理流量重复计算。
- **Windows 代理**：外网连接的流量通常归到代理进程，暂不保证回填到原始客户端。
- **macOS 代理**：尝试按连接匹配客户端与代理，但采样先后顺序、短连接结束和并发请求会影响归属。已有原生代理测试在部分环境未达到 75% 客户端归属阈值；未宣称完整解决这一限制。
- **TUN**：通过流量关系推断转发进程，属于启发式归属；无法可靠识别时保留代理归属，不保证所有 VPN 或隧道组合都能映射到客户端。
- **短连接与采样间隔**：两次快照之间结束的连接可能遗漏尾部统计。第一帧通常只建立基线，不能据此判断流量丢失。
- **多 GPU**：显示最忙设备或引擎的使用率，不是把所有 GPU 百分比相加。

报告统计问题时，请说明系统版本、直连 / 系统代理 / TUN 模式、预期流量来源及复现步骤，避免仅凭历史累计值判断实时采集状态。
