# 2026-11-20 网速统计与代码审查修复

本轮修复代码审查发现的五项问题，重点处理 Windows 下代理下载时上传、下载经常接近的现象。版本仍为 `0.1.0`，下面的安装包已替换此前同名构建。

## 原因与修复

| 问题 | 修复后的行为 |
| --- | --- |
| Windows ETW 只读 PID、字节数，不区分网络连接与本机回环转发 | 解析 TCP/UDP、IPv4/IPv6 的地址，过滤任意端点为 `127.0.0.0/8`、`::1` 或映射 IPv4 回环的事件；普通局域网流量保留 |
| 助手采集与推送使用独立定时器，可能重复发送旧帧；UI 按接收间隔算速率 | 新采样通过条件变量通知推送，UI 跳过重复序号；帧尾携带单调采集时间，按源采样间隔计算速率 |
| CSV 导出在 UI 线程同步读写，打开数据库时还执行迁移和元数据写入 | UI 只启动和轮询后台任务，同一界面同时只运行一个导出；导出使用独立只读连接，正常退出等待导出文件写完 |
| 打包脚本从固定 `target/release` 拷贝，可能取到旧文件 | 使用 Cargo JSON 返回的实际可执行文件路径，编译失败或缺少产物时中止；收集后逐文件校验 SHA256 |
| 进程路径缓存每轮仍查询完整路径并分配 64 KiB 缓冲 | 通过同一进程句柄检查创建时间；身份未变时复用路径，首次查询使用 512 个 UTF-16 字符的栈缓冲，不足时才扩容；缓存清理改用集合查询 |

旧程序的回环问题在审查阶段已复现：一次纯 `127.0.0.1` 传输让正在运行的旧程序记入 **8,388,736 字节下载和同等上传**。本机代理的外网接收与本机发送也因此一起进入统计。该次探针记录由旧程序自动写入历史，本轮没有删除或改写真实历史库。

Windows 的代理外网流量目前仍归代理进程，尚未做连接配对以回填给浏览器。TUN/VPN 虚拟接口的跨层统计也不属于本轮已验证范围。历史库只有按应用汇总后的分钟数据，不能据此准确还原和扣除此前的回环流量。

## 采样与兼容

- 协议继续使用 v1，原帧头和进程条目不变；可选尾部为 `TMT1` 加 `u64` 微秒时间戳。旧解码器忽略尾部，新 UI 可以读取没有时间戳的旧助手帧。
- 新 UI 连接旧助手时仍会跳过重复帧，速率时间回退到接收时间。完整的回环过滤和源时间修复需要同时更新主程序与助手。
- 助手先取走当批事件并记录采集时间，再在 ETW 聚合锁外查询路径。进程查询或管道发送延迟不再改变速率的时间分母。
- 重连、序号回退或源时间回退会重新建立速率基线，保留本次运行已经计入的累计字节。窗口和分钟历史继续按接收时间归档。
- 进程创建时间发生变化时重新查路径；若新身份路径查询失败，显示 `pid N` 并允许重试，不继承已经确认属于旧身份的路径。

## 验证结果

Windows x86_64 本机执行：

```text
cargo fmt --all -- --check
cargo test --workspace --locked --offline
cargo clippy --workspace --all-targets --locked --offline -- -D warnings
git diff --check
```

- **141 项测试通过，1 项交互桌面测试默认忽略**；格式检查和严格 Clippy 通过。
- 网络事件回归覆盖 TCP/UDP 的 IPv4/IPv6 收发、两端回环地址、IPv4 映射回环、普通局域网保留、未知版本与截断输入。
- 模拟代理链的回归中，外网下载 **8 MiB**、外网上传 **1 KiB**，中间所有本机转发都被过滤；最终总量仍恰好为 **8 MiB / 1 KiB**。
- 速率回归注入重复帧、延迟接收和紧接着到达的两帧，保持 **10,000 B/s**，累计字节不重不漏；另覆盖重连、序号回退、源时间回退和旧协议帧。
- 数据库回归让另一个连接持有未提交的写事务，新的只读连接仍成功导出已提交数据，并拒绝写入；不存在的数据库不会因导出而被创建。
- 后台导出回归验证：任务阻塞时调用方仍能继续执行；完成后发送结果并唤醒界面；正常析构等待导出完成。
- 最终 release 程序的 `--export` 空历史验证通过：退出码为 0，返回“还没有历史数据”，没有创建数据库。
- 最终 release 程序通过 `scripts/verify-windows-runtime.ps1` 隔离运行验证（PowerShell 7）：原生任务栏子窗口、透明合成、空白区域命中、单实例、mock 数据隔离、正常退出及子窗口移除均通过，背景采样最大 RGB 差值为 0。

Windows 打包验证：

- 在 PowerShell **5.1.26100.9818** 下运行 `packaging/windows/build.ps1`，启用 `CARGO_NET_OFFLINE=true`；两个 release 程序成功编译，NSIS **3.13** 生成安装包。
- 确认脚本保持 UTF-8 BOM，PowerShell 5.1 语法解析通过。
- 使用隔离脚本夹具注入 Cargo JSON，输出位于含空格的自定义目录及目标平台子目录，同时在默认 `target/release` 放置不同内容的旧文件；收集结果来自自定义目录。
- 模拟 Cargo 失败和缺失助手产物，脚本均在收集前中止，已有打包输入保持原值。夹具没有运行安装器。

本轮未安装新包，也未替换或停止正在运行的提权助手；因此上述结论包括解析/记账回归、系统 manifest 核对和隔离 UI 实际运行，**不代表新版提权 ETW 助手已经完成真实外网定量传输验收**。macOS 原生构建与交互也未在本轮执行；其 21 项纯解析/记账测试包含在上述 workspace 测试中。
